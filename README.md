# 숙소 예약 서비스 — 검색·필터링 구현

에어비앤비 UI를 소재로, 숙소 예약 서비스의 핵심 사용자 흐름 **홈 → 검색 → 목록 → 상세 → 예약 요청**을 실제 서비스 수준으로 구현한 프로젝트입니다. 화면을 따라 그리는 데 그치지 않고, 검색 상태 관리·필터링 로직·인터랙션을 직접 설계하고 구현하는 것을 목표로 했습니다.

## 기술 스택

- **Next.js 16** (App Router, React Server Components)
- **React 19** + TypeScript
- **Redux Toolkit** — 위시리스트 상태 관리 (localStorage 영속화)
- **CSS Modules** — 컴포넌트 단위 스타일
- **Vitest** — 단위 테스트

## 설계 결정

이 프로젝트에서 직접 고민하고 결정한 지점들입니다.

### 1. 검색 상태의 단일 진실 공급원은 URL

검색바에서 여행지/날짜/게스트를 선택하면 `URLSearchParams`로 조립해 현재 탭의 목록 경로(`/rooms`, `/experiences`, `/services`)에 `?location=…&checkin=…&checkout=…&guests=…`를 붙여 이동하고, 목록 페이지(서버 컴포넌트)가 `searchParams`를 읽어 필터링합니다. 홈의 탭도 `/?tab=rooms|experiences|services`로 URL에 둡니다.

- 검색 결과와 홈 탭을 **새로고침·뒤로가기·링크 공유**해도 그대로 재현됩니다.
- 필터링이 서버 컴포넌트에서 일어나므로 검색 상태를 위한 전역 스토어가 필요 없습니다.
- 탭 슬러그와 목록 경로를 같게 맞춰(`src/lib/tabs.ts`), 홈 탭 URL과 검색 이동 경로를 한 표에서 만듭니다.

### 2. 서버/클라이언트 경계 — 데이터는 브라우저로 보내지 않는다

홈·목록·상세 페이지는 전부 **서버 컴포넌트**로, 데이터를 고르고 필터링해 props로만 넘깁니다. `"use client"`는 인터랙션이 필요한 부분(헤더·검색바, 카드 캐러셀, 무한 스크롤 그리드, 상세 화면)에만 둡니다.

- 클라이언트 컴포넌트는 `@/data`를 import하지 않습니다. 홈이 클라이언트 컴포넌트이던 때는 150개 목업 생성기가 브라우저 번들에 들어갔는데, 서버 컴포넌트로 바꾼 뒤 빌드 산출물에서 **클라이언트 청크에 목업 데이터가 0건**인 것을 확인했습니다.
- 상세 갤러리 사진처럼 데이터 풀이 필요한 것도 서버 페이지에서 골라 결과만 넘깁니다.

### 3. 날짜는 표현이 아니라 값으로 저장 (`src/lib/dates.ts`)

숙소의 예약 가능 기간은 `"7월 15일~20일"` 같은 라벨이 아니라 **오늘로부터의 오프셋**(`startOffset`일 뒤부터 `nights`박)으로 저장합니다. 실제 `Date`와 카드 라벨은 화면에 보일 때 오늘 기준으로 계산하므로, 시간이 지나도 목업 데이터가 낡지 않습니다. 검색한 체크인~체크아웃이 숙소의 가능 기간에 **완전히 포함**될 때만 결과에 노출됩니다.

- "오늘"은 실행 환경 타임존과 무관하게 **한국 시간(KST) 자정 기준**으로 정규화합니다. 서버(UTC)와 브라우저가 같은 날짜를 써야 hydration mismatch가 나지 않습니다.
- 빌드 시점에 정적 생성하면 빌드한 날의 날짜가 HTML에 박히므로, 날짜를 그리는 페이지는 모두 요청 시점에 렌더링합니다(홈도 `searchParams`를 읽어 동적 렌더링).
- 순수 함수로 분리하고 달 넘김, 해 넘김, KST 날짜 경계를 Vitest로 검증했습니다.

### 4. 최대 인원은 한 값으로 — 검색·예약카드·API·안내 문구

숙소의 `maxGuests` 하나를 **검색 필터, 예약카드의 + 버튼 상한과 안내 문구, 예약 API 검증, 상세 부제목·소개의 규모 문구**가 함께 씁니다. 한 곳에만 고정 문구("최대 9인")가 남아 있어도, "9명 가능"을 보고 고른 인원이 예약 단계에서 거절되는 모순이 생기기 때문입니다.

- 인원은 **성인 + 어린이**로 셉니다(유아 제외). 예약카드와 서버 검증이 같은 기준을 씁니다.
- 침실·욕실 수는 인원에서 추정해 만듭니다(`src/lib/roomSpecs.ts`).

### 5. 검색 조건은 검색바가 소유 — controlled 팝업

여행지(입력 텍스트·선택 도시)·날짜·게스트 state는 전부 `SearchBar`에 두고, 팝업은 `value`/`onChange`만 받는 controlled 컴포넌트로 만들었습니다. 팝업은 섹션을 옮길 때마다 언마운트되므로, 선택값을 팝업 안에 두면 다시 열 때 사라집니다. 팝업에는 hover·보고 있는 달 같은 **보기 상태**만 남깁니다.

- 자식이 `useEffect`로 부모에 값을 보고하는 패턴을 없앴습니다. 표시 문구(날짜 라벨, 게스트 수)는 state로 따로 두지 않고 렌더링 때 계산합니다.
- 여행지 입력창은 입력값으로 도시 목록을 거르는 자동완성입니다. 목록에는 **실제 데이터가 있는 도시**, 그중에서도 현재 탭에 결과가 있는 도시만 보여줍니다(누르면 0건이 나오는 선택지 없음).
- 상태 전이 로직은 `searchState.ts`로 분리해 Vitest로 검증했습니다.

### 6. 서로 다른 두 DOM을 하나처럼 — FLIP 애니메이션

확장 검색바와 압축 바는 실제로는 별개의 DOM입니다. 전환 시 FLIP(First-Last-Invert-Play) 기법으로 출발 위치/크기에서 도착 위치/크기로 transform을 걸어 하나의 검색바가 morphing하는 것처럼 보이게 했습니다. 홈에서는 스크롤 위치 기반 자동 전환(내려갈 때 80px, 올라올 때 40px — **히스테리시스**로 경계에서의 떨림 방지), 목록/상세에서는 클릭 시 오버레이 확장으로 동작합니다.

### 7. 팝업 컨테이너 재사용

검색바의 여행지/날짜/게스트 팝업은 섹션을 옮길 때 새로 열지 않고 컨테이너 하나를 `left`/`width` 트랜지션으로 미끄러지듯 이동시킵니다. 내부 콘텐츠만 `key`로 리마운트해 이동 방향에 맞는 슬라이드 애니메이션을 적용했습니다.

### 8. 예약 API — Route Handler로 요청-응답 사이클 구현

백엔드가 없는 대신 Next.js Route Handler(`app/api/reservations`)로 예약 API를 직접 만들었습니다. 예약하기 → `fetch` POST → **요청 중(스피너) → 성공(예약 번호) / 실패(에러 메시지 + 재시도)**의 비동기 상태 전이를 모달 하나에서 처리합니다.

- 서버에 의도적인 지연(1초)을 넣어 로딩 UI가 보이게 했습니다. 실패 UI는 랜덤으로 띄우지 않고 **`?demo=fail`로만** 재현합니다(예: `/rooms/1?demo=fail`). 확률 실패는 처음 보는 사람에게 버그로 읽히기 때문입니다.
- 서버 측 검증(날짜 형식, 체크인·체크아웃 순서, 게스트 수, 최대 숙박 인원 초과)은 순수 함수 `src/lib/reservation.ts`로 분리하고 Vitest로 검증했습니다. 요청 중에는 모달이 닫히지 않게 막았습니다.

### 9. 데이터 접근은 API 계층으로 — 무한 스크롤

목록 데이터는 `/api/listings`(필터 + 페이지네이션)를 통해 제공됩니다. 데이터 저장소(정적 배열 150개)는 API 뒤에 숨어 있어, 나중에 외부 API나 DB로 교체해도 프론트엔드 코드는 바뀌지 않습니다.

- **첫 페이지는 서버 컴포넌트가 렌더링**(빠른 첫 화면), 2페이지부터는 클라이언트가 API로 이어 붙이는 하이브리드 구조.
- 바닥 감지는 `IntersectionObserver` — 바닥 400px 전에 미리 요청해 스크롤이 끊기지 않고, 로딩 중에는 스켈레톤 카드를 표시합니다. 요청 실패 시 자동 재요청하지 않고(무한 루프 방지) "다시 시도" 버튼으로 재개합니다.
- 필터·페이지네이션 로직은 `src/lib/listings.ts`로 분리해 서버 컴포넌트와 API가 공유하고 Vitest로 검증했습니다.
- 대량 목업 데이터는 인덱스 기반 **결정적 생성기**로 만듭니다 — `Math.random`을 쓰면 서버와 클라이언트가 다른 데이터를 만들어 hydration mismatch가 발생하기 때문입니다. 상세 갤러리 사진도 같은 이유로 id 기반으로 결정적으로 고릅니다.

### 10. 라우트별 메타데이터 (`generateMetadata`)

상세 페이지 150개와 목록 페이지마다 `<title>`·description·Open Graph(og:title, og:description, og:image)를 만듭니다. 상세는 숙소명·지역·가격, 목록은 검색 조건과 결과 개수가 들어갑니다(예: `해운대 오션뷰 · 부산 · 해운대 · 총액 ₩1,750,000 | Airbnb Clone`).

- 루트 레이아웃의 `title.template`으로 사이트명을 붙이고, 이름·지역·가격 규칙은 `src/lib/listingMeta.ts`에 모아 화면과 메타데이터가 같은 규칙을 씁니다.
- 목록 페이지는 검색 조건 해석을 함수 하나로 두어 페이지와 `generateMetadata`가 공유합니다 — 제목의 개수가 화면 목록과 어긋날 수 없습니다.
- 없는 id는 `generateMetadata`와 페이지 양쪽에서 `notFound()`로 404를 반환합니다.

### 11. 모달 접근성 3종 세트 (`src/hooks/useModalBehavior.ts`)

Escape 닫기 / 배경 스크롤 잠금 / 포커스 트랩(Tab 순환, 닫히면 열었던 요소로 포커스 복귀)을 훅 하나로 묶어 설명·편의시설·예약 확인 모달이 모두 공유합니다.

## 주요 기능

### 홈
- 숙소/체험/서비스 탭 전환 — `?tab=`로 URL에 반영돼 새로고침·공유 가능 (탭 아이콘 비디오 애니메이션)
- 도시·카테고리별 카드 캐러셀 (반응형 노출 개수, 페이지 단위 이동)
- 스크롤 시 검색바가 압축 바로 변형 (FLIP 애니메이션 + 콘텐츠 페이드)

### 검색
- 여행지(자동완성) / 날짜(캘린더 범위, 3개월 뒤까지) / 게스트 수 선택 → URL 파라미터 기반 검색
- 현재 탭에 따라 숙소·체험·서비스 목록으로 이동
- 날짜 필터 — 선택 기간이 숙소 가능 기간에 포함되는 숙소만 노출
- 게스트 필터 — 최대 숙박 인원이 검색 인원 이상인 숙소만 노출
- 검색 결과: 좌측 카드 목록 + 우측 고정 지도 레이아웃, 무한 스크롤(첫 페이지 서버 렌더링 + 이후 API 페이지네이션)
- 결과 페이지에서 압축 바 클릭으로 재검색 (세그먼트 클릭 시 해당 섹션 바로 열림)

### 상세
- 숙소: 이미지 갤러리(서로 다른 사진 5장), 소개(더보기 모달), 숙박 장소 사진, 예약 카드(체크인/체크아웃 캘린더 + 게스트), 편의시설 모달, 위치 지도
- 예약 카드 — 숙소의 최대 인원까지만 게스트를 추가할 수 있고, 안내 문구도 숙소별 인원으로 표시
- 예약하기 — 날짜 미선택 시 캘린더를 먼저 열어 선택 유도 → 날짜·게스트·총액 확인 모달 → 예약 API POST (로딩 스피너 → 예약 번호 발급 / 실패 시 재시도)
  - 실패 UI는 상세 페이지 URL에 `?demo=fail`을 붙이면 확인할 수 있습니다 (예: `/rooms/1?demo=fail`)
- 체험/서비스: 같은 부품을 카테고리에 맞게 재조립 (1인당 가격, 단일 날짜 선택)
- 위시리스트(찜) — 새로고침해도 유지
- 공유하기 — 링크 클립보드 복사

### 접근성
- 모달: Escape 닫기 / 배경 스크롤 잠금 / 포커스 트랩 / 포커스 복귀
- 팝업류 Escape 닫기 (계층적 — 팝업 먼저, 그다음 검색바)
- 검색바 키보드 조작: 섹션·도시 목록·서비스 유형·압축 바 세그먼트가 모두 `<button>` (Tab 포커스, Enter/Space). 키보드로 섹션을 열면 팝업 안으로 포커스 이동, Escape로 닫으면 열었던 섹션으로 복귀, Tab으로 검색바를 벗어나면 닫힘. 숨겨진 쪽 바(확장/압축)는 `inert`라 보이지 않는 요소로 포커스가 들어가지 않음
- 카드: 찜 버튼을 링크 밖 형제로 분리해 `<a>` 안 `<button>` 중첩(HTML 스펙 위반) 제거

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
```

## 테스트

```bash
npm test           # 단위 테스트 1회 실행
npm run test:watch # 파일 변경 감지 모드
npm run lint       # ESLint
```

순수 로직은 컴포넌트와 분리해 Vitest로 검증합니다.

| 대상 | 내용 |
|---|---|
| `lib/dates.ts` | 오프셋 → 날짜 계산, KST 정규화, 달·해 넘김, 라벨 포맷 |
| `lib/listings.ts` | 목록 필터(지역·날짜·인원), 페이지네이션 |
| `lib/reservation.ts` | 예약 요청 검증 |
| `lib/tabs.ts` | 탭 ↔ URL 매핑 |
| `lib/listingMeta.ts` | 상세·목록 메타데이터(title·description·OG) |
| `lib/roomSpecs.ts` | 최대 인원 기반 규모 문구, 인원 계산 기준 |
| `lib/gallery.ts` | 갤러리 사진 결정적 선택(중복 없음) |
| `SearchBar/searchState.ts` | 검색바 상태 전이, 여행지 자동완성 |
| `store/slices/wishlistSlice.ts` | 위시리스트 리듀서 |

```
src/
├── app/                  # 라우트 (홈, /rooms, /experiences, /services + 각 상세) — 전부 서버 컴포넌트
│   └── api/              # Route Handler API — listings(목록/페이지네이션), reservations(예약)
├── components/
│   ├── common/           # Header, SearchBar, CalendarMonth, GuestCounter 등 공용
│   ├── home/             # RoomCard, RoomSection (캐러셀, 클라이언트 아일랜드)
│   ├── listing/          # ListingResults (목록 + 지도), ListingGrid (무한 스크롤)
│   ├── detail/           # 상세 섹션들, BookingCard, Modal
│   └── layout/           # PageHeader (홈·목록·상세 공용 헤더 래퍼, 클라이언트 경계)
├── data/                 # 목 데이터 (숙소/체험/서비스) — 서버에서만 import
├── hooks/                # useWishlist, useModalBehavior
├── lib/                  # 날짜·필터·예약 검증·탭·메타데이터·규모 문구·갤러리 (+ 테스트)
└── store/                # Redux (위시리스트)
```

## 알려진 한계

- 체험·서비스 데이터에는 날짜·인원 정보가 없어, 체험 목록은 검색 조건을 쓰지 않고 서비스 목록은 도시(서울·부산)로만 거릅니다.
