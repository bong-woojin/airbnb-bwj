# 숙소 예약 서비스 — 검색·필터링 구현

에어비앤비 UI를 소재로, 숙소 예약 서비스의 핵심 사용자 흐름 **홈 → 검색 → 목록 → 상세 → 예약 요청**을 실제 서비스 수준으로 구현한 프로젝트입니다. 화면을 따라 그리는 데 그치지 않고, 검색 상태 관리·필터링 로직·인터랙션을 직접 설계하고 구현하는 것을 목표로 했습니다.

## 기술 스택

- **Next.js 16** (App Router, React Server Components)
- **React 19** + TypeScript
- **Redux Toolkit** — 위시리스트 상태 관리 (localStorage 영속화)
- **CSS Modules** — 컴포넌트 단위 스타일
- **Vitest** — 단위 테스트

## 설계 결정

이 프로젝트에서 직접 고민하고 결정한 지점들입니다.

### 1. 검색 상태의 단일 진실 공급원은 URL

검색바에서 여행지/날짜/게스트를 선택하면 `URLSearchParams`로 조립해 현재 탭의 목록 경로(`/rooms`, `/experiences`, `/services`)에 `?location=…&checkin=…&checkout=…&guests=…`를 붙여 이동하고, 목록 페이지(서버 컴포넌트)가 `searchParams`를 읽어 필터링합니다. 홈의 탭도 `/?tab=rooms|experiences|services`로 URL에 둡니다.

- 검색 결과를 **새로고침·뒤로가기·링크 공유**해도 그대로 재현됩니다.
- 필터링이 서버 컴포넌트에서 일어나므로 검색 상태를 위한 전역 스토어가 필요 없습니다.

### 2. 날짜는 표현이 아니라 값으로 저장 (`src/lib/dates.ts`)

숙소의 예약 가능 기간은 `"7월 15일~20일"` 같은 라벨이 아니라 **오늘로부터의 오프셋**(`startOffset`일 뒤부터 `nights`박)으로 저장합니다. 실제 `Date`와 카드 라벨은 화면에 보일 때 오늘 기준으로 계산하므로, 시간이 지나도 목업 데이터가 낡지 않습니다. 검색한 체크인~체크아웃이 숙소의 가능 기간에 **완전히 포함**될 때만 결과에 노출됩니다.

- "오늘"은 실행 환경 타임존과 무관하게 **한국 시간(KST) 자정 기준**으로 정규화합니다. 서버(UTC)와 브라우저가 같은 날짜를 써야 hydration mismatch가 나지 않습니다. 같은 이유로 날짜를 그리는 홈 페이지는 빌드 시점 정적 생성 대신 요청 시점에 렌더링합니다(`connection()`).
- 순수 함수로 분리하고 달 넘김, 해 넘김, KST 날짜 경계를 Vitest로 검증했습니다.

### 3. 게스트 수 필터

숙소마다 최대 숙박 인원(`maxGuests`)을 두고, 검색한 게스트 수를 수용할 수 있는 숙소만 노출합니다. 날짜 필터와 마찬가지로 서버 컴포넌트에서 판정합니다.

### 4. 서로 다른 두 DOM을 하나처럼 — FLIP 애니메이션

확장 검색바와 압축 바는 실제로는 별개의 DOM입니다. 전환 시 FLIP(First-Last-Invert-Play) 기법으로 출발 위치/크기에서 도착 위치/크기로 transform을 걸어 하나의 검색바가 morphing하는 것처럼 보이게 했습니다. 홈에서는 스크롤 위치 기반 자동 전환(내려갈 때 80px, 올라올 때 40px — **히스테리시스**로 경계에서의 떨림 방지), 목록/상세에서는 클릭 시 오버레이 확장으로 동작합니다.

### 5. 팝업 컨테이너 재사용

검색바의 여행지/날짜/게스트 팝업은 섹션을 옮길 때 새로 열지 않고 컨테이너 하나를 `left`/`width` 트랜지션으로 미끄러지듯 이동시킵니다. 내부 콘텐츠만 `key`로 리마운트해 이동 방향에 맞는 슬라이드 애니메이션을 적용했습니다.

### 6. 예약 API — Route Handler로 요청-응답 사이클 구현

백엔드가 없는 대신 Next.js Route Handler(`app/api/reservations`)로 예약 API를 직접 만들었습니다. 예약하기 → `fetch` POST → **요청 중(스피너) → 성공(예약 번호) / 실패(에러 메시지 + 재시도)**의 비동기 상태 전이를 모달 하나에서 처리합니다.

- 서버에 의도적인 지연(1초)과 확률 실패(20%)를 넣어 로딩/에러 UI가 실제로 동작하는 것을 확인할 수 있습니다.
- 서버 측 검증(날짜 형식, 체크인·체크아웃 순서, 게스트 수, 최대 숙박 인원 초과)은 순수 함수 `src/lib/reservation.ts`로 분리하고 Vitest로 검증했습니다. 요청 중에는 모달이 닫히지 않게 막았습니다.

### 7. 데이터 접근은 API 계층으로 — 무한 스크롤

목록 데이터는 `/api/listings`(필터 + 페이지네이션)를 통해 제공됩니다. 데이터 저장소(정적 배열 150개)는 API 뒤에 숨어 있어, 나중에 외부 API나 DB로 교체해도 프론트엔드 코드는 바뀌지 않습니다.

- **첫 페이지는 서버 컴포넌트가 렌더링**(빠른 첫 화면), 2페이지부터는 클라이언트가 API로 이어 붙이는 하이브리드 구조.
- 바닥 감지는 `IntersectionObserver` — 바닥 400px 전에 미리 요청해 스크롤이 끊기지 않고, 로딩 중에는 스켈레톤 카드를 표시합니다. 요청 실패 시 자동 재요청하지 않고(무한 루프 방지) "다시 시도" 버튼으로 재개합니다.
- 필터·페이지네이션 로직은 `src/lib/listings.ts`로 분리해 서버 컴포넌트와 API가 공유하고 Vitest로 검증했습니다.
- 대량 목업 데이터는 인덱스 기반 **결정적 생성기**로 만듭니다 — `Math.random`을 쓰면 서버와 클라이언트가 다른 데이터를 만들어 hydration mismatch가 발생하기 때문입니다.

### 8. 모달 접근성 3종 세트 (`src/hooks/useModalBehavior.ts`)

Escape 닫기 / 배경 스크롤 잠금 / 포커스 트랩(Tab 순환, 닫히면 열었던 요소로 포커스 복귀)을 훅 하나로 묶어 설명·편의시설·예약 확인 모달이 모두 공유합니다.

## 주요 기능

### 홈
- 숙소/체험/서비스 탭 전환 — `?tab=`로 URL에 반영돼 새로고침·공유 가능 (탭 아이콘 비디오 애니메이션)
- 도시·카테고리별 카드 캐러셀 (반응형 노출 개수, 페이지 단위 이동)
- 스크롤 시 검색바가 압축 바로 변형 (FLIP 애니메이션 + 콘텐츠 페이드)

### 검색
- 여행지(도시) / 날짜(캘린더 범위) / 게스트 수 선택 → URL 파라미터 기반 검색
- 날짜 필터 — 선택 기간이 숙소 가능 기간에 포함되는 숙소만 노출
- 게스트 필터 — 최대 숙박 인원이 검색 인원 이상인 숙소만 노출
- 검색 결과: 좌측 카드 목록 + 우측 고정 지도 레이아웃, 무한 스크롤(첫 페이지 서버 렌더링 + 이후 API 페이지네이션)
- 결과 페이지에서 압축 바 클릭으로 재검색 (세그먼트 클릭 시 해당 섹션 바로 열림)

### 상세
- 숙소: 이미지 갤러리, 소개(더보기 모달), 숙박 장소 사진, 예약 카드(체크인/체크아웃 캘린더 + 게스트), 편의시설 모달, 위치 지도
- 예약하기 — 날짜 미선택 시 캘린더를 먼저 열어 선택 유도 → 날짜·게스트·총액 확인 모달 → 예약 API POST (로딩 스피너 → 예약 번호 발급 / 실패 시 재시도)
- 체험/서비스: 같은 부품을 카테고리에 맞게 재조립 (1인당 가격, 단일 날짜 선택)
- 위시리스트(찜) — 새로고침해도 유지
- 공유하기 — 링크 클립보드 복사

### 접근성
- 모달: Escape 닫기 / 배경 스크롤 잠금 / 포커스 트랩 / 포커스 복귀
- 팝업류 Escape 닫기 (계층적 — 팝업 먼저, 그다음 검색바)

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
```

## 테스트

```bash
npm test           # 단위 테스트 1회 실행
npm run test:watch # 파일 변경 감지 모드
```

오프셋 → 날짜 계산·KST 정규화·검색 필터 판정(`src/lib/dates.ts`), 목록 필터·페이지네이션(`src/lib/listings.ts`), 예약 요청 검증(`src/lib/reservation.ts`), 위시리스트 리듀서를 커버합니다.

## 구조

```
src/
├── app/                  # 라우트 (홈, /rooms, /experiences, /services + 각 상세)
│   └── api/              # Route Handler API — listings(목록/페이지네이션), reservations(예약)
├── components/
│   ├── common/           # Header, SearchBar, CalendarMonth, GuestCounter 등 공용
│   ├── home/             # RoomCard, RoomSection (캐러셀)
│   ├── listing/          # ListingResults (목록 + 지도)
│   ├── detail/           # 상세 섹션들, BookingCard, Modal
│   └── layout/           # PageHeader (홈·목록·상세 공용 헤더 래퍼, 클라이언트 경계)
├── data/                 # 목 데이터 (숙소/체험/서비스)
├── hooks/                # useWishlist, useModalBehavior
├── lib/                  # 날짜 유틸 (+ 테스트)
└── store/                # Redux (위시리스트)
```

> 참고: 데이터는 전부 목(mock)이며, 결제는 의도적으로 범위에서 제외했습니다. 예약 흐름은 자체 Route Handler API에 요청을 보내 예약 번호를 발급받는 것까지 구현되어 있습니다.
